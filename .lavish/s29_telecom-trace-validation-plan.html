Filtering our telecom traces down to the core every leader shares makes them the same shape as the leaderboard's, with no change to the agent

The leaderboard's own traces do not agree on extras. Opus 4.5 keeps its reasoning on some turns and writes text beside most of its calls. GPT-5.2 keeps neither, and wraps most of its replies in JSON. What every side shares is what a fine-tuning row holds: the prompt, the customer's words, the agent's text, its calls and their results. So the plan is one filter, run on every file, theirs and ours: it keeps that core and holds the rest back. A prototype of it, run on 899 passed conversations (421 Opus 4.5, 409 GPT-5.2, 69 v2), gives 1 row shape across all of them. Nothing in the agent changes and nothing is thrown away. What a filter cannot change is how v2's conversations read, and the plan measures that instead.

Whatever D0 says, one converter should write every row, and tau-telecom-sft's is already built and tested. This plan should match it, not compete with it. Four things differ, and each is a choice that converter made for its two sources. Its rule 3 keeps each repo changing only itself, so any change to that converter is made there, by its own session.

01 · The goal — keep every detail for optimisation, and export a filtered copy that matches the leaders' rows

keepEverything each turn had, where it already is

tau2's results file for each run, and the Claude CLI's own transcript of each model call. Optimisation reads these, and the filter never touches them.

filterOne function for every file

It turns a tau2 results file, a leader's or ours, into one training row per conversation. The rows hold the core only, in the OpenAI chat fine-tuning shape. The same rules apply to every side, so nothing in a row says where it came from.

measureWhat a filter cannot change

Calls a turn, text beside calls, markdown, length and endings are the agent's behaviour. They are scored against the leaders' range and reported, not forced.

The first draft planned to change what our model layer records and to play a fork set up like the leaders' scaffold. Both are gone. The filter reaches the same row shape without either, and §04 shows the record already holds everything the model gave us.

Corrected from the first draft. It said our model layer drops the text beside calls, the provider's call ids and the reasoning, and that the prompts cannot be recovered. For v2 that was wrong. JSON mode never writes text beside a call and never gets a provider id. The reasoning arrives empty. Every turn's prompt is in its CLI transcript. The drops in llm/core.py are real only in native tool mode, which banking uses and telecom does not.

Where the transcripts are

The Agent SDK runs the Claude CLI once per model call, and the CLI writes a transcript of each call to ~/.claude/projects/-private-var-folders-…-T-tau2loop-sdk/. Each turn's raw_data.id in tau2's file is sdk- plus that transcript's name. The folder holds 52,718 transcripts, 6.0 GB, from every run since 28 Sep 2026; v2's two runs are 5,673 of them, 418 MB.

Why they may not last

They sit outside the repo, so a run folder's immutability does not cover them. The CLI deletes old transcripts after cleanupPeriodDays. Your settings set 3,650 days, but the SDK's sessions load no settings (setting_sources=[]), and I have not checked whether that leaves them on the default of 30 days. M5 copies them to a stable place (D6).

v2's rows will have the leaders' shape but read like v2: one call a turn, nothing written beside a call, little markdown, longer conversations. In one training set, a model learns a blend of the two styles. The filter could merge v2's one-call turns into one turn, but that would invent turns no model wrote, so it does not. Closing these gaps would mean changing the agent's setup, which this plan leaves out. If you want it later, the first draft's 6-task fork (native calls, several calls a turn) is how to find out.

The customer is a different model on each side: gpt-5.2 at low effort for the leaders, Haiku 5.5 at high for us. This project bills only the Claude subscription, so gpt-5.2 cannot be our customer. Customer measures are reported and kept out of the score. C4 now counts messages in a filtered row, which leaves out the customer's device calls. The band widens once all 7 tau2 1.0.1 leaders are read (M4).

08 · The plan — six milestones, no model calls and no change to the agent

  1. M1

    Collect the leaders' telecom traces

    tau2loop leaderboard-fetch --domain telecom reads the board's manifest.json and submission.json files, downloads each text submission's telecom file (D1) to data/external/leaderboard/telecom/ (D4) and writes a committed manifest.json: submission, model, URL, bytes, sha256, tau2 version, customer and pass count. A file whose sha256 changes is refused.

  2. M2

    The filter: tau2loop export-sft

    The prototype made a command (src/tau2_loop/traces/export.py), with Fig 5's rules and one code path for every side. --run <id> or --leader <name>, passed conversations by default, train ids only (D3). It writes rows.jsonl, ready for fine-tuning, and sources.jsonl beside it. The real prompt's sha256 in sources.jsonl is read from the turn's CLI transcript for our rows. Tests run it on fixtures cut from both sides and assert one shape, the unwrap rule (D2), and that a test id is refused.

  3. M3

    The checker: tau2loop trace-check

    It reads tau2 results files and their filtered rows, and writes trace_check.json. The file checks are F1–F9. The row checks are the shape and the four problem counts, and every side must pass them all. The conversation measures are C1–C8 against the band, with the customer measures reported apart. It is deterministic and calls no model.

  4. M4

    Baseline: v2 against the 7 leaders, and each leader against the others

    Filter and score v2's train and test runs with all 7 leaders. Then score each leader against the other six for the ceiling: two standard-scaffold runs are not identical either. The baseline replaces the two-leader numbers in §05–§07.

  5. M5

    Keep the detail: copy each run's CLI transcripts out of the temp folder

    tau2loop archive-sessions --run <id> copies every transcript a run's turns name, agent's and customer's, to data/sessions/<run id>/. That folder is gitignored, with a committed manifest of sha256s. It runs on v2's two runs, 5,673 files and 418 MB (D6). Run folders stay as they are: they are immutable.

  6. M6

    A results page

    .lavish/s30_… shows the three scores across the 7 leaders and v2, the ceiling, a sample of filtered rows from each side, and what stays different and why. Each milestone is its own commit; pushing and the PR wait for your say.

Untouched: llm/core.py, the prompts, agents/telecom/v2/, runner.SIM_RULES (still tau2_loop/2) and every run folder. Cost: M1 downloads 377 MB (D1 = A). Nothing calls a model.
