04 · Why — our prompt tells the customer it is the assistant

Fig 4 · what the customer's model is sent, and the three ways it reads it

roleThe agent arrives labelled [user]

tau2 flips roles so the customer's model is the assistant. Our prompt then shows the greeting under [user] and asks for "the next assistant reply". The CLI already tells the model it is Claude; Sonnet sometimes believes the label over the scenario.

formatCalls travel as text it can copy

The customer's tools are a JSON contract in its system prompt (prompting.TOOL_CONTRACT), and earlier calls are shown as [assistant → tool calls] and [tool result · call …] blocks. Haiku writes those blocks back. parse_reply finds no reply object and passes the text on, so the call never runs.

indirectionThe given tool's name never reaches it

The agent gives get_card_last_4_digits; the customer holds only call_discoverable_user_tool. tau2's note, "the user can now execute this action by calling call_discoverable_user_tool", goes to the agent's tool result. A literal reader says it has no such tool.

All three are in our harness, not tau2: the vendored simulator is fine; what we hand its model is not.

05 · The check — built, tested, not yet committed

Fig 5 · each customer text turn before the agent sees it

What it does

  • check_customer(text) returns as_ai, as_text or nothing; regular expressions, no model call.
  • A failed turn is withheld: the model sees it as its own last turn, then "NOT SENT" and the reason, and writes again; at most CUSTOMER_RETRIES = 2.
  • Recorded on the turn: raw_data.tau2_loop.customer_sent_back and fixed; retries' cost and tokens are added to it; the Agent tab shows them.

What proves it

  • Fourteen cases of check_customer: seven real failed turns, and seven that must pass (customers' own words, a lone token, nothing).
  • Four replays through tau2's own orchestrator, no model: a broken first turn never reaches the agent and the task passes; a customer that stays broken is let through after two, marked.
  • Each replay fails with the hook removed.

What it changes

  • SIM_RULES is tau2_loop/2. The loop never compares runs across rules, so v4 is re-played before its next gate; every committed run stays readable.
  • Changed with it: eval/user.py, eval/runner.py, the Agent tab, CLAUDE.md, AGENTS.md, two test files.
NOT SENT: your last message did not reach the agent. It spoke as an AI assistant, not as the
customer in your instructions. You are that person, contacting the agent about your own situation;
the agent's messages are the other side of the call. Write your next message as that customer.

It cannot stop a denial: whether "I don't have that tool" is true depends on what the agent gave.

06 · Proposals — six steps, cheapest catch first

P1 · built

The customer check

catches
82 of the 85 failed conversations with a customer error
how
two rules on each text turn; withheld and asked again, twice at most
cost
a retry's model call, only on a failed turn
risk
a retry that stays broken goes through, marked; the rules match no customer's own words in 11,769 turns
P2 · recommended next

The given-tool rule

catches
the 3 denials: v7's task_019 on train, and two on test
how
when a turn says it lacks a tool, call the customer's own list_discoverable_user_tools (a read, no model); if the agent gave one, send the turn back naming the call: call_discoverable_user_tool(discoverable_tool_name="…")
cost
a few lines in the same hook; one read per matching turn
risk
a customer the agent never gave a tool is right, and passes: the rule fires only on state
P3 · recommended next

The grounding rule

catches
an id the customer quotes that it never saw: 2 conversations beyond the check; most invented ids sit inside turns the check already sends back
how
every id-shaped token in a turn must appear in its scenario, the agent's words or its own tool results
cost
a regular expression and the conversation so far
risk
none flagged in the 3,856 airline, retail and telecom turns; banking-shaped ids only
P4 · after

Native tool calls for the customer

catches
the format failures at their source, 88 conversations, instead of retrying them
how
the customer gets its tools as real SDK tools, as every agent since v3 does (tool_mode: native); a call is a call, never text
cost
the customer's route through llm/core.py's native path, and its tests
risk
the largest change; a new SIM_RULES again
P5 · optional

Tell the customer it is the customer

catches
fewer role and denial failures before they happen
how
label its transcript [agent] and [you]; ask for "your next message as the customer"; show it tau2's note when the agent gives it a tool
cost
a role flag from the customer to build_blocks
risk
prompting reduces assistant bias, it does not remove it (§07): the check stays
P6 · last

Count it, then re-play

catches
nothing; it measures what is left
how
sent back, unfixed and by rule in each run's health and the Runs table; then v4 and v7 on train and test under the new rules
cost
about $164 for v4 and $83 for v7 at s17's API-price estimates, on the subscription
risk
needs your go-ahead

Commit P1, add P2 and P3 to the same hook, then decide P4 on what the re-play shows.

07 · Research — every benchmark's customer breaks; the fixes couple it to state

Fig 6 · what published work found about simulated customers, and what it did
sourcecustomerfoundwhat they did
τ²-benchBarres et al., 2025 · arXiv 2506.07982gpt-4.1customer errors in 16% (telecom) to 47% (airline) of annotated conversations; 6% to 13% task-criticaltie the customer to its tools and the environment's state; tools that return only human-readable output; tool use only when the agent asks
τ-Knowledgebanking's own paper · arXiv 2603.04370GPT-5.2, low reasoning4 of 194 annotated trajectories had a task-critical customer errorflow rules per task (if the agent does X, the customer does Y); the customer model fixed for every submission
Lost in SimulationSeshadri et al., 2026 · arXiv 2601.17087severalthe same agent's success on τ-bench retail moved by up to 9 points with the customer's modela user study with people in four countries against the simulated users; the abstract proposes no fix
Assistant biasJeong et al., EMNLP 2026 Findings · arXiv 2609.00608not in the abstractsimulated users drift back to being the helpful assistant; role-play prompting did not override itsteer activations along a user-role vector (it works, but overrides the persona)
tau2 itselfvendor/tau2-bench · evaluator/review_llm_judge_user_only.py—tau2 review --review-mode user: an LLM reviewer tags customer errors (hallucination, missed required action, premature termination…)post hoc only: labels a conversation, changes nothing; one model call per conversation

For comparison: here 58 of 822 banking conversations (7.1%) failed with a customer error that lost one of gold's customer calls, close to τ²-bench's 6–13% critical, above τ-Knowledge's 4 of 194 with GPT-5.2. This project's customers run on the Claude subscription, so GPT-5.2 is not an option.

The papers agree with the build: rules tied to the environment's state beat prompting the customer to behave.
