05 · How it's compared — the same 97 tasks, v30 against v8's 8 Oct record with the gate's one-sided McNemar, knowing that the models changed too

what matchesThe same 97 tasks under the same rules

Split v3 (60 train, 37 test), rules tau2_loop/2, seed 300, one trial, concurrency 3. A Sonnet customer at medium, as in v8's runs, but now Sonnet 5.5. The scoring is the same for all 97 tasks, including task_102, which the judge grades with Haiku 4.5 as in v8's runs.

what differsThe design and the model generation

v8 → v30 changed the prompt, the checks, r3 → r20, the steps view and the customer-tools note. The model generation also changed: the agent and the customer both moved from Sonnet 5 to Sonnet 5.5. Because v8 isn't re-run, those two kinds of change can't be pulled apart. v23 is the nearest guide to the model swap alone: v8's design on Sonnet 5.5, with a Haiku customer, scored 43 of 60 and 20 of 37 against v8's 38 and 21.

the verdictPaired, task by task

Each task is fixed (v8 failed, v30 passed), broke (the reverse) or the same. eval/compare.py's one-sided exact McNemar at α = 0.05 runs on each split and on both together. Banking's gate reads test (GATE_ON_TEST). The page reports the verdict and says what it can and can't support.

two side checksRegressions and the customer's effect

First, which of v23's 63 passes v30 now fails, each traced to the change since v23 that touches it: a prompt line, a check, or an r18–r20 job. Second, v30's 34 conversations from 22 Oct (Haiku 5.5 customer, high) against the same tasks today (Sonnet 5.5, medium). That shows how much the customer alone moves v30's results.

06 · Risks — the comparison with v8 mixes the design with the model generation; usage is the one thing that could stop a run

riskwhat the plan does
A usage limit mid-run97 conversations with Sonnet 5.5 on both sides, on the subscription: more usage per conversation than with a Haiku customer. Conversations a limit cuts off are recorded as infrastructure errors. Each run is checked for them before its score is read. A run is never restarted after a limit without your say (v25 was voided this way on 15 Oct).
Not like for like with v8v8 isn't re-run (your call), so v30 against v8 mixes the design with Sonnet 5 → 5.5 on both sides. A significant result says the latest bundle on 5.5 beats the champion's record, not that the design alone does. Promoting v30 on that basis is your call.
The customer leaves the s25 standardExperiments since 15 Oct used Haiku 5.5 at high. These runs use Sonnet 5.5, so they can't be compared with v26's, v27's or v30's own scores on the 34. The side check in §05 measures the customer's effect on those 34 tasks.
The judge stays Haiku 4.5The one model in these runs that isn't at 5.5. It grades only task_102, whose database check passes for v8, v23 and v30 and whose written assertion Haiku 4.5 failed each time. Keeping it grades that task as v8's record did, with no code change.
Test stays held outThe results page shows test task ids and outcomes to you, as s22–s35 did. No optimiser reads .lavish/, and no test conversation or test id reaches a prompt. The next optimisation reads train failures only (banking's optimiser reads all 60 train tasks).
One trialOne trial of 97 can't separate versions a few tasks apart: v26, v27 and v30 passed 11, 10 and 11 of the 34. A second trial (Q4) doubles the runs.
Wall time3–5 hours for the two runs, reported one at a time. A pause between runs is safe, because each run is complete on its own.
