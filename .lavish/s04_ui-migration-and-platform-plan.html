tau2-loop s04 · UI migration to DataAgentBench + central platform backend draft for review · 2026-09-25

Comprehensive review · DataAgentBench explorer vs tau2-loop viewer · branch challenger-20260925

DataAgentBench's explorer is the same app, three iterations ahead. Bring tau2-loop up to it, and put its backend on the central platform.

Both projects optimise one agent against a public benchmark and show the work. They already share a design system (DESIGN.md, tokens.css) and a stack (React 18 + Vite + TS, FastAPI, MLflow). What differs is the information architecture, the navigation grammar, and how much of the loop the UI can actually drive. This plan migrates tau2-loop's nine tabs to DAB's eight, ports the shared frontend machinery, and moves the backend onto nmp-central-ai for both MLflow and Postgres.

5.2 · Postgres onboarding — database tau2

Four edits, in this order. Steps 1 and 2 are the platform's, 3 and 4 are ours; the platform's rules forbid a project-local Postgres service, so nothing is added to any compose file.

  1. Declare it in the platform registry

    Add a database: block to P3 in nmp-central-ai/registry/projects.yaml, beside the existing mlflow: block, then run make db-init and paste the printed block into tau2-loop/.env.

        database:
      name: tau2
      roles: [tau2_owner, tau2_ro]
      extensions: []                       # no pgvector: nothing here is embedded
      env:
        PG_SUPERUSER_URL: superuser        # roles.sql only (D16)
        DATABASE_URL: tau2_owner
        RO_DATABASE_URL: tau2_ro           # what the read-only viewer connects as
      migrate: make db-init
      smoke: make db-smoke
      status: pending
      aws: false                           # D19

  2. infra/roles.sql — one schema, two roles

    Modelled on DAB's, minus the meta schema: τ²'s answer keys are public and already in the repo, so there is nothing to hide from a role. tau2_ro exists so the served app cannot write outside its own POST routes.

    CREATE SCHEMA IF NOT EXISTS tau2_loop AUTHORIZATION tau2_owner;
GRANT USAGE ON SCHEMA tau2_loop TO tau2_ro;
GRANT SELECT ON ALL TABLES IN SCHEMA tau2_loop TO tau2_ro;
ALTER DEFAULT PRIVILEGES FOR ROLE tau2_owner IN SCHEMA tau2_loop
  GRANT SELECT ON TABLES TO tau2_ro;
ALTER ROLE tau2_ro  SET search_path = tau2_loop;
ALTER ROLE tau2_ro  SET default_transaction_read_only = on;
ALTER ROLE tau2_ro  SET statement_timeout = '15s';
ALTER ROLE tau2_owner SET search_path = tau2_loop, public;

  3. src/tau2_loop/data/pg.py + three settings

    Settings gains database_url, ro_database_url, pg_superuser_url with the same local defaults DAB uses, and nothing else reads os.environ. Add psycopg[binary] to pyproject.toml. reachable() decides whether the Review tab is writable — the app must still boot with Postgres down.

  4. Two tables, both append-only

    CREATE TABLE tau2_loop.review (        -- the human verdict on one conversation
  id           bigserial primary key,
  run_id       text    not null,
  task_id      text    not null,
  trial        int     not null,
  judge_reward numeric not null,       -- what tau2 scored it, copied for drift
  verdict      text    not null,       -- agree | disagree | task_broken
  reason       text    not null default '',
  author       text    not null default '',
  code_sha     text    not null default '',
  created_at   timestamptz not null default now()
);
CREATE INDEX ON tau2_loop.review (run_id, task_id, trial);

CREATE TABLE tau2_loop.submission (   -- one row per `tau2 submit prepare` (s03)
  id           bigserial primary key,
  domain       text    not null,
  run_ids      text[]  not null,
  agent_model  text    not null,
  user_model   text    not null,
  trials       int     not null,
  pass_hat_k   jsonb   not null,
  avg_cost_usd numeric,
  pr_url       text,
  created_at   timestamptz not null default now()
);

    Newest row per (run_id, task_id, trial) is the current review — DAB's golden table uses the same append-only shape, and it is what makes a changed verdict auditable.

Rule zero, honoured No postgres service is added to any compose file, no port is hardcoded, no URL is hardcoded, and no DROP DATABASE appears anywhere. make db-backup DB=tau2 before the first migration.

7 · Risks, failure modes and open questions

Ranked. R-1 and R-2 are live today, not introduced by this plan.
IDRiskMitigation
R-1The red accent contradicts DESIGN.md. Both projects' DESIGN.md say frontend/src/tokens.css is the token block "verbatim"; tau2-loop's now diverges, and --accent also means "pass" (.v-ok, .chip.ok, .status.ok, tr.pro). Migrating to DAB's UI while the two projects' palettes disagree makes every shared component look wrong in one of them.Decision Q3. The recommended answer keeps the red brand and adds an --ok token for pass semantics, which is what this artifact uses — and which DESIGN.md's "project extension" precedent (DAB's --red, --syn-*) already allows.
R-2/gate renders blank and the Runs nav link did not change route when last exercised. Root cause not yet diagnosed.Diagnose at M0, under the new route tests, before any page is rewritten — otherwise the bug is carried into the new IA.
R-3The public demo has no Postgres. tau2-loop deploys as a read-only image (DEMO_MODE=1, M5 parked on an App Runner quota). A Review tab that assumes a database breaks the demo.Postgres reachability is a runtime capability, not a requirement: pg.reachable() gates the write route and the form. Tested explicitly at M5.
R-4Scope. DAB's Optimise.tsx is 1,129 lines and its Golden.tsx is 804. Reproducing them literally is weeks, not days.M3 ports the structure (rounds list, round-opens-in-place, three steps) over tau2-loop's existing ledger data, not DAB's scorecard machinery. Q1 sets how far this goes.
R-5Role-name collision. Postgres roles are cluster-global (D15); make db-init refuses a duplicate.tau2_owner / tau2_ro appear nowhere in the registry today. Confirmed by reading it — but re-check at M4 before running db-init.
R-6Trace volume. A τ² conversation runs to 40+ turns across four domains × 114 tasks × 4 trials. A trace per conversation is ~1,800 traces per full submission run.Keep DAB's CUT = 2000 trimming and PLATFORM.md rule 4 (never MLFLOW_TRACE_FULL=1). Consider tracing only failed conversations on full-split runs — open question.
R-7The submodule is never edited. vendor/tau2-bench is pinned at 2174a60; the Leaderboard ingest reads from inside it.Ingest to data/index/leaderboard.json and commit that, exactly as DAB ingests upstream — the app must work from a bare clone.
R-8Review authorship. The author column has no auth behind it; a local single-user app cannot prove who typed a verdict.Default to the git user, record it as claimed-not-verified, and keep it out of any published number until it matters. Open question if reviews ever become evidence in a submission.

Assumptions this plan rests on

  • The four τ² domains stay the unit of navigation (they are DOMAINS in config.py and the key of every registry, split and ledger).
  • runs/<id>/ stays the record. Nothing in §5 moves a benchmark fact into Postgres.
  • The Field Guide stays the design system — no Tailwind, no component library, per both AGENTS.md files.
  • Python stays 3.12 / uv / ruff / mypy strict; the frontend stays React 18 + Vite + plain CSS.
