Audit · banking_knowledge against airline · agent input tokens

Banking burns 8.8× airline's tokens re-sending its own searches

The Agent SDK is sealed: a bare call costs 441 tokens. The waste is ours. tau2's KB_search returns ten whole documents, about 16k characters, per search. The transcript carries every one of them to the end of the conversation. Because we send that transcript as one text block, the prompt cache never reads any of it back.

update · fix A built and tried

A now sends one block per turn with a cache mark on the last. The five conversations used an earlier version of the mark. On the same 5 banking tasks, 85% of agent input came back from cache, and price-weighted input fell from 7.27M to 1.74M (−76%). The version now in the code reads back one more call's worth, about 1.20M replayed on the same calls. Everything is stopped again. See §11.

The cache matches a prompt's prefix at block boundaries. Our prompt has one user block, the whole transcript, and it changes on every call, so the only match is a byte-identical retry. Airline has the same problem, at a ninth of the size.

caveat · the meter

Anthropic doesn't publish how the subscription meter weighs a cache write or read. "Price-weighted" on this page means the API ratios the SDK reports, not the meter. Raw token counts, which fixes C–E cut, are the other reading.

11 · Trial — 85% of agent input came from cache

You chose A, a probe and five conversations. It took three versions to get A right on Sonnet 5, the model the runs use:

  1. A block per turn. Haiku read back the previous call. Sonnet read only the system prompt, both in the probe and in the first live attempt, which I stopped after one conversation.
  2. Plus a cache mark on the block the previous call ended on. This is the version the five conversations ran. Reads worked but ran one call behind: the CLI's own mark sits on a block after ours that no later prompt repeats.
  3. Plus a cache mark on the last block instead. This is the version now in the code. The probe reads back the previous call's whole prompt, less about 335 tokens. The API allows four marks and the CLI uses three, so there's room for only one of ours.

caveat · one trial each

Each task ran once before and once after. The conversations took different paths (114 agent calls before, 117 after), so raw tokens and results move for reasons A doesn't touch, and 1 → 1 passed is not a score change. What A does change is the read share, and that is measured on every call. A first attempt with the blocks alone (runs/20260930T012736Z_banking_knowledge_v1_custom, stopped after one conversation) read only the system prompt on Sonnet, which is how the need for the mark showed up. A also rewords the prompt slightly: the ask now reads "follows, one block per turn", and the closing </conversation> tag is gone.

Measured, with version 2: per agent call, price-weighted input fell from 63.8k to 14.9k (−77%). Replayed on the same calls, the shipped version 3 would total 1.20M against 7.27M before (−84%).
