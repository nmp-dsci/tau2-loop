Telecom's answering agent can run on DeepSeek Flash through Pydantic AI by swapping one model call, and step one costs about $5–10 to score against v2's 45 of 74 and 24 of 40

ConvFinQA-agent's newest work (25 Oct) ran its Claude champion's prompt, unchanged, on deepseek-flash with thinking at high, through Pydantic AI, and saved every conversation as a trajectory file that its SFT builder turned into training rows. This plan does the same for tau2-loop's telecom agent: a new version, v3, is v2 with its model call routed to DeepSeek; the customer, the tools, the split and the scoring stay as they are. Step one plays it on v2's 6 smoke tasks, then all 74 train and 40 test, and a results page answers whether it needs optimising before its traces teach a student in tau-telecom-sft.

02 · The seam — tau2 keeps the loop; v3 swaps the one model call each turn makes

  1. tau2 stays in charge.

    Its orchestrator holds the conversation, runs each tool call in the telecom environment and gives the customer its turn. Nothing under vendor/tau2-bench changes.

  2. One call is swapped.

    LoopAgent.ask() (agent/factory.py:255) is the agent's only model call per attempt. When agent.yaml says backend: pydantic_ai, it calls a new llm/open_backend.py instead of tau2's generate(). Telecom has no helper, checks or guidance, so nothing else in the agent sees a difference.

  3. Pydantic AI never runs a tool.

    The backend turns tau2's history into Pydantic AI messages and tau2's 13 tool schemas into external tools, so the agent run stops at the first tool call and returns it unrun, the way core.py's native mode defers its stub tools today. The reply comes back as tau2's AssistantMessage: text, tool calls, cost, tokens, and DeepSeek's reasoning in raw_data.

  4. Kept out of core.py.

    The subscription core keeps its pinned imports (tests/test_core.py) and the agent image's three files; the customer and judge go through it exactly as now.

05 · Milestones — build with no model calls, a 6-task smoke, then train and test, reported one at a time

  1. M0 · Build (no model calls; one commit).

    Dependencies as in §03. AgentConfig.backend, carried by fork_version, tau2loop fork --backend and make fork BACKEND=. llm/open_backend.py and the routing in ask(). The key kept to the agent: dropped from subscription_env() so an optimiser session (it has Bash) never sees it, already blanked by sealed_env for the customer, never in run files. check_billing() still runs first, so the demo image (DEMO_MODE=1) refuses. RunMeta and the MLflow billing tag record agent deepseek-api, customer subscription. The price table, and the trajectory file on the run folder and the MLflow run. The trace-file clash fixed for new runs: names cut at 80 characters overwrite each other, so v2's test run has 33 trace files for 40 conversations and train 64 for 74. AGENTS.md and CLAUDE.md's billing rule amended (§07).
    Tests on Pydantic AI's FunctionModel, no API: history round trip, reasoning put back on tool-call turns, tool definitions from tau2's schemas, the AssistantMessage shape, the key absent from every file a run writes, the demo refusal, a fork carrying backend. Then uv run pytest -q and make lint.

  2. M1 · Fork and smoke (about $0.30–0.50).

    make fork DOMAIN=telecom FROM=v2 BACKEND=pydantic_ai MODEL=deepseek-flash EFFORT=high TOOL_MODE=native WHY="…" writes v3. It plays v2's 6 smoke tasks (v2 passed 3 of 6), one trial, the Haiku 5.5 customer at high: make eval DOMAIN=telecom AGENT=v3 SPLIT=train TASKS="…". The report: passes, turns, tool errors, JSON-wrapped replies, any 400, reasoning tokens, cost and the model DeepSeek served.

  3. M2 · Train, then test (about $5–10 together).

    make extend joins the smoke to all 74 train tasks; reported. Then the 40 test tasks; reported. One trial each, concurrency 3, the same customer and rules as v2, so every number is like for like. The estimate scales v2's volume (train 27.4M input and 1.35M output tokens over 1,780 turns) at ConvFinQA's Flash prices and cache rate, with thinking adding output; a running total stops the run at your cap.

  4. M3 · Results page and your call.

    v3 against v2 question by question, McNemar on train and test, by persona (v2's Hard persona: 6 of 36) and symptom, how conversations end, cost and tokens, and the failure modes in v3's own traces. The page asks the §06 question.

Not in this plan: a teacher pass for tau-telecom-sft. It needs a customer that isn't Claude, an answer to the prompt question, and likely several trials for enough rows (§07). It gets its own plan after M3.

06 · Optimise first? — the train pass count is the yield, since tau-telecom-sft keeps passed conversations only

tau-telecom-sft's filter F1 keeps a conversation only if it passed, so a teacher's train passes are its rows per trial, and a teacher that passes no more than the student it teaches adds nothing. The bars below are a proposal for M3's call; change them in §08's notes.
