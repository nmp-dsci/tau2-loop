02 · How — a train failure becomes a rule, and the rule rewrites whole jobs

Fig 3 · from a train failure to a test question, in r21
  1. Find the deciding step, on train only.

    For each train failure, the graded difference (loop.optimiser.diff_block) and the conversation show which workflow step the agent followed: the s39 diagnosis, re-read on v31's runs. 6 train failures have one: task_020, task_027, task_063, task_073, task_084, task_086. Test failures appear on this page so you can see what each rule should reach. No test outcome, test id or gold value reaches workflow_rag.

  2. Write a general reading rule.

    Each rule says how to read a passage and never names a task, a customer or a gold value (the s22 rule). It goes in the three prompts that write and check jobs: audit.md (the auditor that judges every step against the full documents it cites), merge.md and rag_agent.md (research).

  3. Check it against train gold.

    Offline, before anything is built: a rule that any train gold answer contradicts is dropped, because it would be fitting rather than reading. For example, liability in the 14 train gold debit disputes that set it is 50 12 times and 500 2 times, never the disputed amount (R1).

  4. Rebuild the jobs.

    r21 starts from r20's library (53 jobs). It re-merges the r18 research sessions of task_027, task_063, task_084, task_086 under r21's prompts: no new research, as r20 did. Each merge runs r20's three parts. The auditor reads the job's current version against every document it cites, now applying R1–R5. The merge writes the job and accounts for every step it drops. The post-audit reads the result. The rubric (code) checks each merge, sends a failure back once, and keeps the previous version if it fails again.

  5. Gate 0, offline.

    Diff each of the 7 rewritten jobs, r20 to r21. Every step §03 names must have changed, and no quote-backed step may be lost (rubric D8, D12). If a targeted step is unchanged, stop before anything plays.

  6. Read it.

    v32 = make fork FROM=v31 WORKFLOWS=r21: only the library differs from v31. Then the gated runs in §05.

never in r21: a test outcomea test task ida gold valuea rule naming a case

Why whole jobs: the audit doesn't patch the failing step. It re-judges every step of the job against the documents. That includes steps that test questions' research put there (r3 researched every test question from its customer's script, never gold, and r18 researched 7 more). So a rule learned on train reaches a test question's steps without any test result being used. 03 · What — five rules, each from a train failure, each one gold agrees with

R1A field takes a value its document lists

When a document lists the values a field can take (tiers, codes, set amounts), the step sets one of them, chosen by the document's own condition. It never computes a new value from them (the lesser of, capped at, the amount itself) unless a passage states that arithmetic for that field.

r20 today · filing_a_debit_card_transaction_dispute · file_disputethe lesser of $50 and the amount, the lesser of $500 and the amount, or -1
r21 expected

customer_max_liability_amount is 50, 500 or -1, doc _031's tiers, whatever the amount

learned from (train)task_084
train gold check14 train gold disputes set liability: 50 ×12, 500 ×2, the amount ×0
test it can reachnone new: v31's check D2 already forces a tier, so in task_085 liability is now right. R1 makes the job agree with the check.

R2A condition comes from the step's own passage and the records

A condition that withholds or narrows an action (only if, do not file when, must be X to get Y) must be stated by the passage the step quotes, for that action, and read from the records. A condition borrowed from another procedure, or inferred from what the customer says they looked at or accepted, is removed or turned into a question about a fact.

R3The passage that names the case decides

When two passages disagree, the one that names the case decides over one that reaches it only through a broader class. r20's gap rule says this for prohibitions; r21 says it for every conflict.

R4A rounding gap is not a discrepancy (your s25 rule 21, binding)

A recorded figure equal to the amount times the right rate, rounded either way, is right: never a discrepancy, never offered for dispute or correction. A discrepancy is a figure that implies another rate, category or promotion window. r21 makes this decide what counts as a discrepancy even where a document states how the system rounds.

r20 today · submitting_a_cash_back_dispute · ruleAlways round points down to a whole number (floor). A recorded figure equal to the amount times the correct rate rounded up or to the nearest whole number is higher than the correct points, so the transaction is overpaid.
r21 expected

test it can reachtask_017 (Hilton, 1,159 recorded against 1,158) and task_026 (9 false one-point flags buried GitHub's real 1,530-point error)

R5A fee doesn't make a requirement optional

A requirement a document states (keep at least X) still holds when the document charges a fee for missing it. A product whose requirement the customer can't meet is dropped, not kept with the fee priced in.

04 · How it reaches test — through jobs that train and test questions share

There is one library and one lookup. find_workflow is a word match over all 53 jobs, with no split filter, and it showed each question a job researched from that question's own session in 96 of 97 conversations.
